# 开发准则

> 沉淀日期：2026-09-30
> 来源：打印体系从零到闭环的实战复盘（中间变量审核 → 数据驱动 → 校验防线 → 组件统一）
> 定位：**必须遵守的规则**，每条都有真实踩坑案例背书。新功能开发前过一遍。

---

## 一、数据层：不假设，单一权威

### 1.1 「DB 列名 ↔ 记录键」转换必须复用数据层同一函数

- **规则**：任何模块需要做列名/键名转换，一律调用 `Model._from_db_field` / `_to_db_field`，禁止自写命名假设或手写字符串。
- **案例**：打印模块用 PRAGMA 拿下划线列名（`player_name`），而 `get_all()` 返回驼峰记录键（`playerName`），两处各自硬编码 → 模板取值恒空，打印页全部空白。全表只有 `award` 这种两种写法恰好相同的键侥幸命中。

### 1.2 同一事物只有一个权威定义源

- **规则**：路径、目录名、分类、常量——只允许在一个地方定义，其他地方 import；受用户配置影响的值从配置派生，不写死。
- **案例**：打印归档目录写死 `'MediaArt_Archives/07_打印归档'`，同时无视 `config.json` 的 `archivePath` 和 taxonomy.py（自称 single source of truth）的既有定义。收敛为：taxonomy 定义目录名常量，打印模块用 `get_archives_dir()` 跟随配置拼路径。

### 1.3 清单类数据从真实数据派生，不从结构猜

- **规则**：可选字段、枚举项等「跟数据走」的清单，从实际记录派生（键的并集）；写死或从表结构猜都会与页面数据脱节。
- **案例**：打印字段目录最初从 PRAGMA 派生，与证书管理页真实数据不一致；改为遍历真实记录键并集后，台账新增字段自动出现在勾选列表，零代码跟进。

### 1.4 通用过滤用分层规则，字面量集合先校准

- **规则**：过滤「什么能上界面」时分层判定：显式黑名单（已知内部字段，语义优先）→ 命名语义（`At` 结尾=时间戳、`Id` 结尾=系统引用，主键豁免）→ 值形态 → 值长度。**值形态的字面量集合必须先查真实数据再定**。
- **案例**：布尔标记规则若把「是/否」也算进去，会误杀「晋级情况」这类业务字段——先查库发现真实布尔列存的是 `0/1`，才敢只认纯布尔字面量。

## 二、交互：不静默，防线在出口

### 2.1 入口宽松，出口把关，过程透明

- **规则**（本项目数据流三原则，用户已确认）：
  - **入口宽松**：导入不做校验，数据先进来，工作台里随时编辑完善；
  - **出口把关**：真正有后果的动作（打印、发布、删除）前做校验，有问题**弹窗列明细、默认中断**，绝不静默放行；
  - **过程透明**：编辑预览中不得拿标签冒充数据——无数据的字段半透明/灰显标注，填充率可见。
- **案例**：「6 个字段只显示 4 个」——语种、指导老师台账全空，打印渲染成空 div「看不见」；预览层回退显示标签造成误导。修法：预览半透明标注 + 打印前空值弹窗 + 勾选列表填充率徽标。

### 2.2 校验失败的默认出口是中断

- **规则**：有疑点的操作默认拦截，放行需要用户显式点「仍要继续」；但纯拦截不能卡死合法场景（如整列本来就没数据的字段），所以是「确认后放行」而非硬中断。

### 2.3 新页面直接用统一组件，不用原生元素

- **规则**：下拉框一律 `CustomSelect`（支持 option 插槽与 optgroup 分组），弹窗用 `useConfirmDialog`，提示用 `useToast`。凡是全局替换过的原生元素，新代码里禁止再出现。
- **案例**：5 处原生 `<select>` 漏网，全部出自新写的打印页面——「全局替换完」不等于「以后不会再冒出来」。长期方案：check-static 加规则，模板中出现 `<select` 即报错。

## 三、前端规范

### 3.1 设计语言与结构

- UI 遵循「宣纸墨韵」主题（米白底/墨黑字/朱砂红），颜色、间距一律用 CSS 变量（`--paper` / `--line` / `--cinnabar` / `--stone`），不硬编码色值（组件库第三方 fallback 除外）。
- 全 UI 去 emoji，纯文字标签。
- 禁用内联样式堆砌与裸 div，语义结构用语义类（`.det-row` / `.chk` / `.side-block`）；宽度等一次性布局可用 `style="width:.."`。
- 暗色模式是正式场景：新增控件必须双主题验证（对比度问题曾出现在资料类型输入框白底白字）。

### 3.2 兼容与检测

- 浏览器全局 API（`FontFace` 等）统一 `window.X` + `typeof` 能力检测，不裸写标识符——check-static 对「运行时才炸」的未声明引用会拦截。
- 兼容历史数据时兼容「所有曾写入过的格式」（如列名兼容驼峰 / `dbColumn` / 历史下划线三种存法），旧数据不迁移也能正确工作。

### 3.3 坐标与几何

- 做拖拽/键盘微调前先想清坐标系（本项目画布 y 向下为正，方向键映射曾写反自查修正）。
- 排版辅助能力按「所见即所得」推导：对齐吸附按渲染后的视觉边缘算（考虑 align 锚点与 translate），不是简单对坐标值。

## 四、工程流程：证据驱动

### 4.1 先基线，再动手

- **规则**：改代码前先跑测试基线（pytest，当前 79 项），改完对比回归；前端改动跑 `check-static.mjs`。基线不过先修基线。
- 本项目交付节奏：**静态分析 + 基线测试 → 改代码 → 基线对比 → 真实数据冒烟 → 下结论**。

### 4.2 冒烟测试用真实库数据

- **规则**：验证「能不能用」必须连真实 DB 跑一遍完整链路（模板 + 真实记录 → 生成 → 检查产物），mock 数据测不出「列名对不上」这类问题。
- **案例**：打印取值 bug 用存量模板 `tpl-test-1` + 真实证书记录才实锤；「字段丢失」质疑用最新归档件 grep 字段框数量才定论为「字段全空而非丢失」。

### 4.3 报「改了没用」先核对运行进程

- **规则**：改了 `server/` 后端代码必须重启服务进程才生效。用户反馈改动无效时，**先核对运行中进程的代码版本**（新增接口 404 = 进程陈旧的指纹），再查代码逻辑。
- **案例**：`/api/print/fonts` 404 + 「只有奖项显示」两个表象，根因都是 8080 跑着旧进程——旧版取值 bug 的特征（只有两种写法相同的键能命中）恰好印证。

### 4.4 用户报的问题先复现实锤，再下结论

- **规则**：bug 报告前充分核查，避免假阳性（曾误读 key 造成过误报）；结论要有可复现的证据（查询结果、产物文件、接口响应），「应该是」「大概」不算结论。

## 五、资产与边界

| 目录 | 领域 | 规则 |
|---|---|---|
| `resources/` | 资源中心（素材库） | 只放素材，功能资产不入内 |
| `data/` | 运行时用户数据 | 功能资产（打印底图/字体）放这里，不入素材扫描、被 .gitignore 排除 |
| `MediaArt_Archives/` | 归档输出 | 按 taxonomy 分类落盘，路径从配置派生 |
| `dist/` | 纯构建产物 | 可随时 `npm run build` 重新生成，清理安全 |

- **规则**：功能产生的资产（上传底图、字体）不与用户素材库混放——素材扫描会把它们当成杂乱文件；各自有独立目录并在启动时做幂等迁移。
