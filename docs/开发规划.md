# 媒体艺术展览工作台 - 开发规划

> 版本：1.1.0  
> 更新日期：2026-04-02  
> 当前状态：架构过渡期，Vue 3 前端依赖旧架构全局对象，需建立独立 API 层

---

## 架构现状说明

```
当前实际依赖链（问题根源）：
  src/ (Vue 3)  →  window.DataStore (js/data-store.js 旧架构)  →  Python server.py
```

**所有 Pinia Store 均通过 `window.DataStore` 读写数据**，这意味着：
- Vue 3 新架构无法独立运行，强依赖旧架构全局对象注入
- 任何旧架构初始化失败（含财务 500 错误）都会拖垮新架构
- 无法渐进式替换旧代码

**目标架构（解耦后）：**
```
  src/ (Vue 3)  →  src/services/ (HTTP API 封装)  →  Python server.py
```

### 1.2 建立 src/services/ HTTP API 层（核心任务）

**目标：** 让 Vue 3 Store 直接调用后端 API，不再依赖 `window.DataStore`

**文件规划：**
```
src/services/
├── http.js          # axios 封装，统一 baseURL/错误处理/auth token
├── project.js       # 项目相关 API
├── organization.js  # 机构相关 API
├── player.js        # 选手相关 API
├── finance.js       # 财务相关 API
├── knowledge.js     # 知识库 API
├── auth.js          # 登录/鉴权 API
└── index.js         # 统一导出
```

**改造 Store 方式（以 finance.js 为例）：**
```javascript
// 改造前：依赖全局 window.DataStore
const loadRecords = () => {
  const waitForDataStore = () => {
    if (window.DataStore && window.DataStore.data) {
      financeRecords.value = window.DataStore.data.finances || []
    }
  }
}

// 改造后：直接调 REST API
import { financeApi } from '../services/finance'
const loadRecords = async () => {
  const res = await financeApi.list()
  financeRecords.value = res.data || []
}
```

## 三、长期规划（3 - 6 个月）

### 3.1 后端拆分重构

**当前问题：** server.py 单文件 3500+ 行，Python 内置 http.server 单线程阻塞

**推荐方案：** FastAPI（异步、自带 OpenAPI 文档、类型安全）

**迁移策略（渐进式，不停服）：**

| 阶段 | 内容 | 说明 |
|-----|-----|-----|
| Phase 1 | server.py 按模块拆分 | 不换框架，先解决单文件问题 |
| Phase 2 | 引入 FastAPI，双服务并行 | 端口并行运行，逐模块切流量 |
| Phase 3 | 全量切换 FastAPI | 停用旧 server.py |

**拆分目标结构：**
```
server/
├── main.py              # 入口，启动 FastAPI
├── routers/
│   ├── auth.py          # 认证路由
│   ├── projects.py      # 项目路由
│   ├── players.py       # 选手路由
│   ├── organizations.py # 机构路由
│   ├── finances.py      # 财务路由
│   ├── archive.py       # 归档路由
│   └── users.py         # 用户路由
├── models/              # Pydantic 数据模型
├── database/            # 现有数据库层（保留）
└── utils/               # 现有工具（保留）
```

### 3.2 测试体系建设

| 层 | 框架 | 优先级 |
|---|-----|-------|
| 前端单元 | Vitest | P1 |
| 前端 E2E | Playwright | P2 |
| 后端接口 | pytest + httpx | P1 |

### 3.3 性能优化

| 优化项 | 优先级 | 方案 |
