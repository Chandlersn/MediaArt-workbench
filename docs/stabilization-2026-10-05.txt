MediaArt 工作台：核心业务链打磨记录
日期：2026-10-05

依据：本轮直接阅读当前源码，运行真实 API、SQLite、文件系统及浏览器流程；未采用历史审查报告作为结论依据。

本轮修复

1. 登录与首页
   访客首页不再请求受保护数据并弹出阻挡操作的登录框。
   登录后重新加载业务展示，退出时卸载受保护页面并回到访客首页。
   资料配置快捷入口指向正确页面；选手表单标明实际必填项；页面明确引用构建后的图标资源。

2. 资料收集
   Store、列表和详情统一使用扫描返回的 materials，按当前阶段判断缺料。
   成功扫描得到空数组时以磁盘结果为准；只有扫描失败时才回退历史记录。
   详情等待选手加载完成再扫描；上传、删除后刷新状态；修复删除按钮参数不匹配。
   原实现会把“报名表”“身份证”等准确类型折叠成“个人信息”目录类型，导致上传后仍显示缺料。
   新上传将准确类型与阶段保存在 data/material_metadata.json，扫描读取这份文件索引。
   同名上传不覆盖原文件；索引加线程锁并原子写入，写失败撤销本次新文件。
   索引随系统内的重命名、移入回收站和恢复移动；失败保留原文件并反馈失败。
   下载、预览及删除优先匹配准确类型；跨目录同名文件不会串用，类型匹配存在歧义时拒绝操作。
   选手、项目和机构详情的相关请求补齐资料类型，保留旧文件的目录分类兼容。

3. 证书与打印
   重复同步更新已有证书时保留原批次，不再产生空批次；新证书保留对应选手的项目关联。
   切换查看批次保存为本地偏好，查看者无需发业务写请求。
   打印生成、归档和重打保留“证书号 + 批次”身份；旧记录没有批次时明确标注。
   指定批次不存在时返回失败，不再误取同号的其他批次证书。
   同名且同秒的打印归档使用独立文件，避免相互覆盖。
   修复重打按钮绑定空字符串后一直处于禁用状态的问题。

4. 启动与回收站
   启动入口验证 Python 是否可运行及版本，兼容本地虚拟环境和显式解释器配置。
   端口已被使用时核对工作台状态及首页，避免把其他服务当成启动成功。
   后端进程提前退出时及时报错；跳过浏览器的配置在各启动分支均生效。
   回收项 id 与文件夹重命名只接受单目录名，并验证最终路径边界。

验收方式

前端回归：npm test
后端回归：python -m pytest tests/python -q -p no:cacheprovider
静态检查：npm run lint:quiet；npm run check
浏览器验收：npm run test:e2e

浏览器操作真实界面，连接独立临时目录中的真实后端；不会使用正式业务库。
完整步骤：登录与首次引导 → 项目/机构/选手创建 → 其他阶段资料不抵扣当前阶段
→ 当前阶段上传、刷新、同名跨类型附件下载与删除、重新上传 → 证书重复同步 → 模板编辑与底图解码
→ 打印预览、归档回看、按原批次重打 → 备份、修改、恢复 → 退出登录。
测试最后核对业务数据、浏览器脚本异常和 API 失败响应。
测试指南见 tests/README.md；最近一次浏览器报告见 test-results/report/index.html。

验证结果

前端：133 项通过。
后端：247 项通过，1 项因本机普通符号链接权限跳过；另有 Windows 目录联接越界用例已实际通过。
ESLint 错误检查、静态检查、参数检查和构建通过。
Edge 无头浏览器：1 条完整业务链通过，脚本异常和 API 错误响应均为 0。
构建仍提示通知模块同时静态和动态导入；该提示不影响构建成功，本轮未做额外拆包优化。

范围与限制

这里只屏蔽实际 window.print 调用；真实文档生成、预览及归档均参与验收，尚未验证实体打印效果。
未在本轮构建和安装 Electron 安装包，未据此声称所有页面和所有平台都已验收。
没有准确元数据的旧附件继续按目录分类，不根据文件名猜测其类型；需要准确区分的旧资料可重新按相应类型上传。
设置页的业务备份仍不包含附件文件、资料文件索引、打印历史与提交链接；本轮未将它改为整机备份。
手工迁移完整工作台时需连同附件与 data/material_metadata.json 一起保留。
