## 一、Electron 打包核心问题

### 1.1 打包配置要点

#### 1.1.1 package.json build 配置

```json
{
  "build": {
    "appId": "com.mediaart.workbench",
    "productName": "媒体艺术展览工作台",
    "asar": false,  // 开发阶段建议关闭，便于调试
    "directories": {
      "output": "dist-output"
    },
    "files": [
      "dist/**/*",      // Vite 构建产物
      "electron/**/*",  // Electron 主进程
      "node_modules/**/*"
    ],
    "extraResources": [
      {
        "from": "server.py",      // Python 后端
        "to": "server.py"
      },
      {
        "from": "server",         // 后端模块
        "to": "server"
      },
      {
        "from": "js",             // 静态 JS 文件（重要！）
        "to": "js"
      },
      {
        "from": "data",           // 数据文件
        "to": "data",
        "filter": ["**/*", "!backup/**/*"]
      }
    ]
  }
}
```

**常见错误：**
- `server/` 目录未打包 → Python 启动失败，ImportError
- `js/` 目录未打包 → 前端 JS 文件 404
- `data/` 目录未打包 → 数据文件丢失

#### 1.1.2 extraResources vs files

| 配置项 | 用途 | 文件位置 |
|-------|-----|---------|
| `files` | 打包到 asar/app 目录 | `resources/app/` |
| `extraResources` | 打包到 resources 目录 | `resources/` |

**路径映射规则：**
- `extraResources` 文件在 `process.resourcesPath` 下
- `files` 中的文件在 `app.getAppPath()` 下

### 1.2 路径变量对照

| 变量 | 值（打包后） | 用途 |
|-----|-------------|-----|
| `process.resourcesPath` | `resources/` | extraResources 根目录 |
| `__dirname` (main) | `resources/app/` | Electron 主进程目录 |
| `BASE_DIR` (Python) | `process.resourcesPath` | Python 资源目录 |
| `DATA_DIR` | 用户数据目录 | 持久化数据 |

### 1.3 静态文件服务

#### 1.3.1 常见路由模式

```python
# 打包后的目录结构
# resources/
#   ├── app/
#   │   └── dist/
#   │       ├── index.html
#   │       ├── js/
#   │       └── css/
#   ├── server.py
#   ├── server/
#   └── js/  ← 独立打包的 JS 目录

class WorkbenchHandler(BaseHTTPRequestHandler):
    def do_GET(self):
        parsed = urlparse(self.path)

        # /index.html → resources/app/dist/index.html
        if parsed.path == '/index.html':
            file_path = os.path.join(STATIC_DIR, 'dist', 'index.html')

        # /js/xxx → resources/js/xxx
        elif parsed.path.startswith('/js/'):
            file_path = os.path.join(BASE_DIR, parsed.path[1:])  # 去掉开头的 /

        # /dist/xxx → resources/app/dist/xxx
        elif parsed.path.startswith('/dist/'):
            file_path = os.path.join(STATIC_DIR, parsed.path[1:])
```

#### 1.3.2 路径拼接注意事项

```python
# ❌ 错误：路径拼接错误
file_path = os.path.join(BASE_DIR, '/js/xxx')  # 结果含多余分隔符

# ✅ 正确：去掉开头的 /
file_path = os.path.join(BASE_DIR, parsed.path[1:])

# ✅ 正确：使用 os.path.join 自动处理
file_path = os.path.join(STATIC_DIR, 'dist', unquote(parsed.path[1:]))
```

### 2.1 模块导入问题

#### 2.1.1 打包后导入失败

**问题：** `ImportError: cannot import name 'xxx' from 'server'`

**原因：** `server/` 子目录未打包到 `extraResources`

**解决：**
```json

  {
    "from": "server",  // 打包整个 server 目录
    "to": "server"
  }
]
```

def ensure_default_admin():
    """服务器启动时确保存在管理员账号"""
    data_file = os.path.join(DATA_DIR, 'workbench_data.json')

    # 读取或创建数据结构
    if os.path.exists(data_file):
        with open(data_file, 'r', encoding='utf-8') as f:
            store_data = json.load(f)
    else:
        store_data = {
            '_version': '2.3',
            'projects': [], 'organizations': [], 'players': [],

            'realName': '系统管理员',

        with open(data_file, 'w', encoding='utf-8') as f:

## 三、前端静态资源问题

### 3.1 JS/CSS 文件 404

**排查步骤：**
1. 检查 `extraResources` 是否包含 `js/` 目录
2. 检查后端路由是否处理 `/js/` 路径
3. 检查 `BASE_DIR` 变量是否指向 `process.resourcesPath`

### 3.2 Vite 构建与静态文件

**问题：** Vite 打包后，`index.html` 中的 `<script src="js/xxx.js">` 不会自动处理

**原因：** Vite 只处理 `type="module"` 的脚本，普通 `<script>` 标签会被保留原样

**解决：** 确保后端正确映射 `/js/` 路由到 `resources/js/` 目录

### 3.3 模块导出问题

```javascript
// ❌ 问题：module.exports 在浏览器中不生效
const CryptoUtils = { ... }
if (typeof module !== 'undefined' && module.exports) {
  module.exports = CryptoUtils
}

// ✅ 正确：直接定义全局变量
const CryptoUtils = { ... }
// 或
window.CryptoUtils = CryptoUtils
```

## 四、密码加密问题

### 4.1 前后端加密流程

```
前端：password → encodeURIComponent → btoa → Base64 → 后端
后端：Base64 → decode → bcrypt 验证
```

### 4.2 bcrypt 验证示例

```python
import bcrypt, base64

stored_hash = 'JDJiJDEyJHNodjZROTFpMGI2L2ZRZUVmRWFvNGU3WUc5LkxmVmJrVTRtWUxsWmgyYVQ3UkJCR2RVZHBH'
password = 'admin123'

# 验证密码
decoded_hash = base64.b64decode(stored_hash.encode())
result = bcrypt.checkpw(password.encode(), decoded_hash)
print(result)  # True
```

### 4.3 密码哈希生成

```python
import bcrypt, base64

def hash_password(password):
    salt = bcrypt.gensalt()
    hashed = bcrypt.hashpw(password.encode(), salt)
    return base64.b64encode(hashed).decode()

def verify_password(password, hashed_password):
    decoded = base64.b64decode(hashed_password.encode())
    return bcrypt.checkpw(password.encode(), decoded)
```

## 五、数据结构问题

### 5.1 常见初始化错误

**问题：** `DataStore.data.notifications.filter is not a function`

**原因：** `notifications` 字段未初始化为数组

**解决：** 在初始化时确保所有数组字段：
```python
for key in ['projects', 'organizations', 'players', 'finances', 'users', 'auditLogs', 'notifications']:
    if key not in store_data or not isinstance(store_data[key], list):
        store_data[key] = []
```

### 5.2 增量存储问题

**问题：** 数组被保存为对象 `{"0": {...}}`

**原因：** `IncrementalStore` 的 `_set_by_path` 方法将新路径误判为对象

**解决：** 添加类型检查和转换逻辑
