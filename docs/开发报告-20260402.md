### Task 2：修复财务接口 500 错误（P0）

**文件：** `server/database/db.py`、`server.py`

#### 根因分析链

```
前端 FinanceAPI.create/update/delete
  → DataStore.save()
  → POST /api/data/save（全量保存）
  → server.py save_data()
  → db.py DataStore.save_all_data()
  → 事务中 DELETE FROM projects 触发外键约束失败
  → 异常被吞 → 返回 500
  → server.py 用 send_error(500) 返回 HTML
  → 前端 response.json() 解析 HTML 报错
```

#### 修复内容

**`server/database/db.py`**

1. 在事务开始时加 `PRAGMA foreign_keys = OFF`，结束时恢复
2. 改为先清子表再清父表、先插父表再插子表的顺序（防外键约束）
3. 新增 `_get_table_columns(table, conn)` —— 动态通过 `PRAGMA table_info` 获取表列名，带 `_table_columns_cache` 缓存
4. 新增 `_upsert(table, data, conn)` —— 通用过滤字段 + `INSERT OR REPLACE`，过滤掉 schema 中不存在的字段（如前端 project 对象里的 `materials`、`folder_name` 等）
5. 重构 `_save_projects / _save_organizations / _save_players / _save_finances / _save_users / _save_material_types / _save_knowledge / _save_notifications` 全部改用 `_upsert`
6. 所有 `_save_*` 方法加 `isinstance(x, list)` 和 `isinstance(item, dict)` 双重类型防御（发现 `notifications` 字段在 load 返回时是 `{'0': {...}}` 格式的 dict 而非 list）

**`server.py`**

7. 最外层 `except` 从 `send_error(500)` 改为返回标准 JSON：
   ```json
   {"success": false, "message": "..."}
   ```

#### 验证结果

```
save_all_data 结果: True
finances after save: 11
record persisted: True
```

### Task 5：建立 `src/services/` API 层

**新增文件：** `src/services/http.js`、`src/services/dataService.js`  
**改造文件：** `src/stores/finance.js`、`project.js`、`organization.js`、`player.js`、`knowledge.js`  
**修改文件：** `src/main.js`

#### `src/services/http.js`

底层 fetch 封装：
- 统一注入 `Authorization: Bearer <token>`
- 统一处理非 JSON 响应（`parseResponse`）
- 导出 `get / post / put / del` 四个方法

#### `src/services/dataService.js`

全量 load/save 单例服务：
- `load()` —— 首次发起请求，内置并发保护（`_loadPromise`），后续复用缓存
- `reload()` —— 强制刷新
- `getData(key)` / `setData(key, val)` —— 读写内存数据切片
- `save()` —— 全量持久化到后端
- `isLoaded()` —— 状态检查
- `mountLegacyBridge()` —— 将 `dataService` 桥接到 `window.DataStore`，保持旧 `js/` 代码兼容性

#### 5 个 Pinia Store 改造

去掉原来的「轮询等待 `window.DataStore` 就绪」反模式（`setInterval` 每 100ms 检查 `window.DataStore` 是否存在），改为：

```js
// 旧方式（反模式）
const timer = setInterval(() => {
  if (window.DataStore?.isReady?.()) {
    clearInterval(timer)
    records.value = window.DataStore.data.finances || []
  }
}, 100)

// 新方式
await dataService.load()
records.value = dataService.getData('finances') || []
```

#### `src/main.js`

启动时调用 `mountLegacyBridge()`，将 `dataService` 挂载到 `window.DataStore`，保证遗留 `js/` 代码在过渡期能正常工作。

### 2.2 Electron 启动失败（未解决）

#### 问题 1：`electron.exe` 缺失

**现象：** `node_modules/electron/dist/electron.exe` 不存在  
**原因：** npm install 时 Electron 二进制下载失败（网络/代理问题）  
**已修复：** 手动从 npmmirror 下载 `electron-v28.3.3-win32-x64.zip` 并解压到 `node_modules/electron/dist/`，同时修正 `path.txt` 内容为 `electron.exe`（去掉多余的 `dist\` 前缀）

#### 问题 2：Electron 启动后立刻退出，弹出 Error 对话框

**现象：** 启动后窗口标题为 `Error`，随后退出  
**根因：** `electron/main.cjs` 在 `app.ready` 中无条件调用 `startPythonServer()`，使用 `py` 命令（Windows py 启动器）启动 Python，但：
  1. 系统可能没有 `py` 启动器
  2. `:8080` 已被手动启动的 server 占用，导致端口冲突或权限报错
  3. 启动失败后 `error` 事件触发 → 弹出错误对话框 → `app.quit()`

**已修改（`electron/main.cjs`）：**
1. Python 命令改为优先使用 Accio 内置 Python（动态检测 `%APPDATA%\Accio\pre-install\` 目录），找不到再回退到 `python`
2. `app.ready` 增加预检：若 `:8080` 已在监听，跳过 `startPythonServer()`

**当前状态：** 修改已写入，但**尚未验证 Electron 能成功显示窗口**。本次测试中每次 Electron 进程启动后均在 10 秒内退出，没有产生任何日志输出，无法确认具体退出原因。

**怀疑的额外原因：**
- `checkServerReady` 函数可能尚未定义（`main.cjs` 中用 `waitForServer` 内部封装，需确认 `checkServerReady` 是独立函数还是需要新增）
- `package.json` 的 `"type": "module"` 与 Electron 加载 `.cjs` 文件的兼容性

## 五、关键架构备忘

```
前端请求链（新）：
Vue 组件 → Pinia Store → dataService.load/save → fetch /api/data/load|save → Python server → SQLite

前端请求链（旧，过渡期并存）：
Vue 组件 → Pinia Store → window.DataStore（=dataService bridge）→ 同上
遗留页面 → js/data-store.js → window.DataStore → 同上

后端只有两个数据接口：
GET  /api/data/load  → 全量读取（从 SQLite 或 JSON 文件）
POST /api/data/save  → 全量写入（写 SQLite + JSON 备份）
```

**核心约束：** 在建立细粒度 REST 接口之前，每次 save 都是全量覆盖，存在并发写入数据丢失的风险（当前是单用户桌面应用，风险可接受）。
