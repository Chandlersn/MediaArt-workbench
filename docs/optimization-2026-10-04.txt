MediaArt Workbench 优化与修复说明
日期：2026-10-04

本轮已经修改源码并重新生成 dist，重点是权限边界、数据保存可靠性、备份恢复以及关键页面的操作正确性。判断和验证来自实际源码、隔离数据库、真实 HTTP 静态服务测试及前端回归。原始审查报告作为修复前记录保留。

一、已落实的修复

1. 静态文件与账户权限
   - server/main.py、server/config.py：默认仅监听 127.0.0.1；没有前端构建时不再将项目根目录作为静态文件目录。
   - data/ 只开放打印底图、字体目录。数据库、JWT 密钥、备份、源码及隐藏文件不能通过静态 URL 获取；禁用目录列表。
   - 检查 URL 编码、Windows 反斜杠、盘符、尾部空格/点和真实路径边界，同时检查自动追加的 index.html，防止路径穿越及链接越界。
   - server/users/routes.py：修改密码绑定已认证账户，拒绝指定其他用户；保留首次登录修改密码流程。
   - server/resources/routes.py：普通保存按数据所属模块检查编辑权限；删除已有业务记录另查删除权限；账户和服务端日志只能走专用接口。
   - 普通数据加载不携带密码哈希。完整备份、导入、恢复和同步操作限定管理员。业务页面需要的字典可以按查看权限读取，不能借此获得设置写权限。

2. 防止丢失数据和并发覆盖
   - server/database/db.py：快照保存使用单个写事务，任何记录校验或 SQL 写入失败都回滚整批数据，并向接口报告失败。
   - 逐段生成版本摘要，保存时在同一事务内比较。过期快照返回 409，本次不写入；不同业务段的独立修改可分别保存。
   - 检查重复主键、数据结构与新增无效外键；兼容历史数值 ID，不自动清除存量异常关联。保存结束后恢复外键约束。
   - 数据读取使用一致快照。保存只读取和计算修改段的版本，避免每次保存项目都扫描全部证书与日志；普通页面也不再加载完整日志和通知历史。
   - 数据库连接按数据库路径和线程隔离，初始化脚本不会意外提交外层事务。
   - src/services/dataService.js：仅提交明确修改的段，冻结排队请求的内容。读取返回副本；只有保存成功才同时更新缓存内容及版本，失败内容不会夹带到下一次保存。
   - 各业务 Store 先确认加载成功，再允许修改。原始版本跟随各 Store，不会借用其他页面刷新的版本覆盖旧数据。
   - 项目、机构、选手、财务的读写串行执行，成功后更新界面。知识库、证书、清单失败后恢复原状态；分类与打印模板失败后保留原列表并提示。
   - 快速连续勾选清单、连续保存等操作按顺序使用已确认的新版本，不再出现界面看似成功、实际丢掉后一次修改的问题。

3. 业务流程
   - 项目、选手编辑保留原记录 ID；机构、财务新建表单先加载已有数据。加载失败时禁止提交并显示错误。
   - 知识库修改类型会将原条目移至目标分类，保留 ID，不再静默丢失修改。
   - 证书编号模板必须包含有效序号变量；生成时检查唯一性并限制尝试次数，避免固定模板导致无限循环。
   - src/services/http.js：并发 401 请求共享一次登录刷新。刷新失败时所有等待请求都结束；单次请求最多重试一次，撤销的凭据直接返回登录要求。
   - 多级 targetPath 上传保留全部目录层级，并拒绝 Windows 盘符及非法控制字符。
   - electron/main.cjs：退出时只结束本次应用启动且仍存活的 Python 子进程，不再按 python.exe 名称或 8080 端口批量结束进程。

4. 备份与恢复
   - 备份直接读取服务端一致快照，不采用浏览器可能过期的缓存。
   - JSON 导出、导入和恢复覆盖备份实际提供的业务段，包括证书、证书设置、打印模板、检查清单、归档配置等；不再只恢复六个业务数组。
   - 导入会移除来源数据版本，整批校验后恢复。旧备份缺失的数据段保持现状；不完整或非法记录导致整体拒绝，现有数据保持原样。
   - 模板未知扩展字段保留。管理员导出、恢复账户后，密码哈希仍可正常校验；缺少密码的旧脱敏账户快照不会覆盖有效账户。
   - SQLite 迁移备份和数据库恢复使用在线 backup API，包含已提交的 WAL 数据，避免仅复制主文件遗漏事务。
   - 同一秒创建多份备份使用独立目录，并兼容备份列表和轮转规则。
   - 界面已明确：JSON 业务数据备份不包含附件文件、打印历史和提交链接；不能将它当作整个工作目录的完整备份。

5. 检查工具
   - tests/run.js 会等待异步测试与 hooks，导入失败、异步异常和超时均使测试失败；增加子进程回归验证，避免错误地显示全绿。
   - scripts/check-params.mjs 改为扫描模块化后端，支持模块内同名函数、路由分支、参数辅助函数和前端表单参数，并加入解析器固定样例自检与空覆盖检测。
   - 暂缓的 SubmitLinkModal 通过有理由的单文件保留名单说明，没有为了通过检查而删除该组件。

二、最终验证结果

执行环境：Windows，Node.js 22.23.3，Python 3.12.14。

  npm test                         105 项通过，0 项失败
  pytest tests/python              168 项通过，1 项跳过，0 项失败
  npm run lint:quiet               通过
  npm run check                    通过
  npm run build                    通过，dist 已重新生成
  git diff --check                 通过

跳过项为 Windows 原生符号链接创建测试，当前权限不允许创建链接；另有模拟真实路径解析的越界测试覆盖对应检查逻辑。

参数扫描覆盖 14 个后端路由模块、102 个路由分支、220 个函数，前端 71/71 个 API 路径匹配到处理函数，其中 40 个路径同时提取到两端参数。它是静态线索工具，不能替代运行时接口测试。

生产构建仍有一个非阻断提示：notificationService 同时被静态与动态导入，因此不会单独拆分为动态块。没有构建错误。

新增回归位于 tests/python/test_*regressions.py、tests/python/test_resource_safety.py 和 tests/unit/ 中的数据保存、前端流程、登录刷新、Electron 进程及测试执行器相关文件。验证使用临时数据库、临时文件或模拟后端；未执行真实业务数据迁移、恢复或清空。

三、生效方式与验证边界

重新启动本项目后端及应用，并刷新已打开页面，使前后端同时使用新的版本协议。旧页面不带版本的保存会被拒绝，提示刷新后重试。

默认地址现在是 127.0.0.1。需要局域网访问时，应在启动进程前设置 WORKBENCH_HOST；.env.example 仅作配置示例，不会自动加载。

本轮已验证源码、接口/存储回归和生产构建，尚未完成 Electron 图形界面的逐页人工操作、实际打印机验证，也未生成新的安装包。若使用既有安装包，它不会自动获得本工作目录中的修改。
